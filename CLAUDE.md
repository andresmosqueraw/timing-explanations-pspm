# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Supporting code for the ICPM 2027 paper (LaTeX sources live outside this repo, in `3-escribir-paper/conferencias/paper1/`; build there with `latexmk -pdf -interaction=nonstopmode -halt-on-error main.tex`). The paper explains *when a PPO policy acts* (the margin `ΔQ = log π(intervene|s) − log π(wait|s)` on the states where it acts, `ΔQ_wait = −ΔQ` where it waits) with Integrated Gradients, pairs it with a risk explanation of the outcome predictor behind the state, and checks both with a deletion test. **The paper's policy is `pools.DEFAULT_VARIANT = "cate"`** on the BPIC logs (6-feature state, one case per episode, `models/variants/ppo_<log>_cate.zip`) and the single SimBank checkpoint; every script defaults to it, and `--variant released` reproduces the earlier four-feature results (`*_released.json`). Numbers quoted in the paper come from the committed JSONs here; regenerate them before changing a number in the manuscript.

## Commands

Always use the repo's virtualenv (`.venv`, Python 3.14; `pip install -r requirements.txt`). No Makefile, no linter config.

```bash
.venv/bin/python -m pytest test_dual_level.py test_xai_suite.py -v   # unit tests (toy/untrained PPO, ~1 min)
.venv/bin/python -m pytest test_xai_suite.py -k lime -v               # one test
.venv/bin/python fidelity_test.py            # Section 7 deletion test -> fidelity_results.json (~2 min)
.venv/bin/python compute_gain_table.py       # Section 5.3 gain table -> gain_table_results.json (--simbank-rows all|decision)
.venv/bin/python run_xai_suite.py            # literature XAI methods+metrics -> xai_suite_results.json, figures/out/xai/ (~10 min)
.venv/bin/python run_xai_suite.py --logs BPIC2017 --quick 60 --n-lime 30 --stability-calls 3 --out /tmp/x.json  # smoke run
.venv/bin/python run_risk_suite.py           # risk level (TreeSHAP on the retrained CatBoost) -> risk_results.json, figures/out/risk/
.venv/bin/python run_effect_suite.py         # effect level (TreeSHAP per arm, phi^CATE) -> effect_results.json, figures/out/effect/ (~5 min)
TIMING_PAPER_FIGURES=<paper>/figures .venv/bin/python figures/make_figures.py   # Figs 1-4 straight into the manuscript
TIMING_PAPER_FIGURES=<paper>/figures .venv/bin/python figures/make_three_level.py   # Fig 5 (three-level card with plain readings + "in plain terms" sentence)
TIMING_PAPER_FIGURES=<paper>/figures .venv/bin/python figures/make_mockup.py        # Fig 6 (web mock-up; effect card fills once effect_results.json exists)
# both read risk_results.json + effect_results.json; plain-language feature readings live in figures/plain.py
```

Retraining the two lower-level models (`risk_model.py`, `effect_model.py`; needs the prepared logs). `effect_model.py --logs BPIC2017` takes ~75 min, almost all of it in the liblinear propensity grid (4 workers, ~2 GB each); use `pkill -f '^\.venv/bin/python effect_model\.py'` to stop it (an unanchored `pkill -f effect_model` kills the calling shell too).

## Architecture

- `paths.py` is the single source of every input/output path; each has a `TIMING_*` env override. `data/*.csv` and `data/loan_log_*` are symlinks/copies of third-party logs and are git-ignored.
- `pools.py` defines the state pools every script must share: the 500-case evaluation pool (`bpic_pool`/`simbank_pool`, seed 123, one prefix per case) and the full decision-point pools for the gain table. Read its docstring before touching `available_resources`: the BPIC logs have no live capacity, so the evaluation pool *cycles* it through 0..3 while the full pool holds it at 3 (the training value). SimBank's column is real (synthetic congestion from `build_resources.py`). SimBank is evaluated on every event (`rows="all"`); the `rows="decision"` variant is degenerate (proxy constant) and kept only as a diagnostic.
- `dual_level.py` holds the differentiable heads over the SB3 `ActorCriticPolicy` (`MarginHead`, `WaitMarginHead`, `CriticHead`, branch-wise logit heads), the Integrated Gradients implementation (128-step straight path, reference = pool mean), the Captum multi-method comparison and `deletion_test` (guided / random×20 / anti-guided masking to the reference, paired SE). `dual_level_study` is the full 2×2 study; `fidelity_test.py` runs only the wait-side part the paper reports.
- `xai_methods.py` / `xai_metrics.py` / `xai_plots.py` / `run_xai_suite.py` reproduce the PPM-explainability literature (SHAP, LIME + CSI/VSI, permutation, ALE; parsimony, functional complexity, monotonicity, LOD, ConsisXAI reducts/core/AIC/BIC, cross-method agreement) on the same heads and pools. Every attribution function returns `phi` with `states.shape`, so `deletion_test` accepts any of them. `xai_metrics.FAMILIES` maps the four state features onto the event/case/control-flow families the reference metrics need. Documented deviations from the reference code: LIME continuous surrogate by default, +0.5-adjusted weight of evidence, `k=2` for LOD.
- `risk_model.py` retrains the outcome predictor behind the state (Shoush & Dumas's CatBoost, ensemble size 1) from the prepared logs under `PeerJ2023/prepared_data/` (git-ignored; `TIMING_PREPARED_LOGS`), using their split/encoding semantics reimplemented incrementally in `encode_prefixes` (verified against their materialised pipeline in `test_risk_model.py`; `foreign/common_files/` is their code, one path patched). Label `deviant` = application not accepted (BPIC) / case cancelled (SimBank, our label). `run_risk_suite.py` explains `logit P(deviant)` with TreeSHAP on the pool's prefixes (matched by case id + prefix_nr; the RL CSV is exactly their test split), computes the Stevens & De Smedt metrics with real event/case/control-flow families, the deletion test, and two-level cards (risk + timing). Key data facts: `deviation = 1 - predicted` where class 1 is the *bad* outcome, so `deviation = 1` means "predicted to end well"; on BPIC2012 `reliability == deviation` exactly.
- `effect_model.py` retrains the third model behind the state: CausalLift's two-model estimator (per-arm `XGBClassifier(max_depth=3, n_estimators=100, lr=0.1)` with IPW weights from a `LogisticRegression` propensity), Y=1 deviant, T = the case's `treatment` flag, one-hot categoricals, `time_to_event_m` dropped. `run_effect_suite.py` explains logit p_T and logit p_U with TreeSHAP summed back to raw attributes, takes φ^CATE = φ^{p_T} − φ^{p_U}, runs the deletion test on the effect log-odds ratio, and draws three-level cards. On SimBank the estimator is fit on the four events both arms share (every HQ contact in the log happens at event 5, every skip at event 9/10) and the untreated arm is a `ConstantArm` (skipping always cancels); `simbank_resources/add_effect_features.py` scores every event into `simbank_resources/data/simbank_time_contact_hq_with_effect.pkl` (`paths.SIMBANK_EFFECT_PKL`, columns `Proba_if_Treated/Untreated`, `y1/y0 = 1[p < 0.5]`, i.e. predicted *good* outcome, so the reward pays where the contact is expected to save the application).
- Policy variants: `pools.VARIANTS` + `paths.variant_model()` → `models/variants/ppo_<log>_<variant>.zip`. `cate` = `--extra-features Proba_if_Treated Proba_if_Untreated --episode case --reward-scale 0.01 --ent-coef 0.3` (the only recipe that intervenes). SimBank's `cate` checkpoint is `models/variants/ppo_simbank_cate.zip`, trained by `simbank_resources/train_ppo_simbank.py --data <effect pkl> --extra-features Proba_if_Treated Proba_if_Untreated --reward-scale 0.01 --ent-coef 0.3`; `--variant released` on SimBank is the uncertainty-proxy checkpoint with the 4-feature state (`paths.simbank_pkl(variant)` picks the pkl). Negative results kept with manifests: `cate_stream` (released stream episodes: intervening forfeits the +50/+100 per-row rewards of unrelated cases), `cate_noent` and `cate_ent002` (per-case episodes but the actor collapses to never-intervene within ~5k steps; approx_kl and entropy reach 0 while the critic still learns V(ite>0) ≪ V(ite≤0)). A hand rule "intervene at the first positive-effect event" returns 859/case vs 594 always-wait on BPIC2012, so the target policy is learnable from the state. Always-wait is optimal under the released state (P(ite>0 | s) ≤ 0.27 everywhere vs. a ≈0.6 per-row break-even). Per-case oracle beats always-wait in 35% of BPIC2012 cases and 3.6% of BPIC2017 cases. `fidelity_test.py --variant <v>` also runs the intervene-side test when ≥30 intervene states exist.
- `foreign/train_ppo_fast_rl_prescriptive_monitoring.py` is the environment the BPIC checkpoints were trained in: Shoush & Dumas's *released* 4-feature state (relative_position, reliability, deviation, n_resources) and reward (cost 25 / gain 50 / gain_res 50), not the 11-feature state of their published paper. A resource is consumed only by the intervention, which ends the episode, so the policy never saw `available_resources ≠ 3` during BPIC training. This is disclosed in the paper's limitations; do not "fix" it silently.
- `simbank_resources/` contains the SimBank pipeline: `build_resources.py` (Poisson arrivals + greedy server assignment; an extension of ours, not SimBank's design), `train_ppo_simbank.py` (`SimBankHQEnvFast`, whose `_df` is also what `pools.load_simbank` reads so features cannot drift), `tune_cost.py` (one-off diagnostic). `ite_proxy` there is a z-scored uncertainty proxy, not a causal effect estimate.
- `models/` and `simbank_resources/models/` hold the checkpoints with `_manifest.json` (seed, steps, provenance, and the history of failed SimBank runs), `_monitor.csv`, `_training_curve.csv`. The stray `_vecnormalize.pkl` is unused: the shipped checkpoint was trained without VecNormalize.

## Conventions

- Results are compared against the committed JSONs; `fidelity_results.json` reproduces bit-for-bit (checked under numpy 1.26 and 2.5). If a change alters numbers, say so explicitly and update the paper's tables (Sections 5.3, 6, 7) in the same change.
- Wait states are `margin <= 0` (equivalently `wait_margin >= 0`); intervene action index is 1.
- Scripts print a human-readable summary and write JSON; figures go to `figures/out/` (git-ignored) unless `TIMING_PAPER_FIGURES` / `TIMING_XAI_FIGURES` redirect them.
- Nothing has been committed in this working tree yet for the `paths.py`/`pools.py` refactor, `foreign/`, or the XAI suite; `run_dual_level_ppo.py` is staged for deletion. Check `git status` before assuming history.
