# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Supporting code for the ICPM 2027 paper (LaTeX sources live outside this repo, in `3-escribir-paper/conferencias/paper1/`; build there with `latexmk -pdf -interaction=nonstopmode -halt-on-error main.tex`). The paper asks *how the risk, effect and timing explanations of a PsPM policy compose*: the timing justification (`ΔQ = log π(intervene|s) − log π(wait|s)` on the states where the policy acts, `ΔQ_wait = −ΔQ` where it waits, attributed with Integrated Gradients) is propagated to the prefix attributes through the risk explanation (TreeSHAP on the outcome predictor) and the effect explanation (TreeSHAP per arm of the causal-effect estimator), and the propagation is checked against a direct attribution of the whole chain (`compose.py`). **The paper's policy is `pools.DEFAULT_VARIANT = "cate_retrained"`** on the BPIC logs: the `cate` recipe (6-feature state, one case per episode, reward scale 0.01, ent_coef 0.3; 600k steps on both BPIC logs) trained on the *coherent* state that `build_retrained_state.py` builds by scoring the prepared log's test split with the retrained risk and effect models (`data/retrained_state_<log>.csv`, `models/variants/ppo_<log>_cate_retrained.zip`), so the two lower levels explain exactly the numbers the policy reads. `--variant cate` is the same recipe on Shoush & Dumas's shipped CSV (`*_cate.json`, whose lower-level explanations therefore explain *other* numbers: 26 % / 39 % of BPIC2012 / BPIC2017 pool decisions flip when that state is rebuilt from the retrained models), and `--variant released` the earlier four-feature design (`*_released.json`). SimBank keeps its single `cate` checkpoint. Numbers quoted in the paper come from the committed JSONs here; regenerate them before changing a number in the manuscript.

## Commands

## Architecture

- `paths.py` is the single source of every input/output path; each has a `TIMING_*` env override. `data/*.csv` and `data/loan_log_*` are symlinks/copies of third-party logs and are git-ignored.
- `pools.py` defines the state pools every script must share: the evaluation pool (`bpic_pool`/`simbank_pool`/`sepsis_pool`, seed 123, one prefix per case of *every* test case: `N_CASES` is set above every split's size) and the full decision-point pools for the gain table. Read its docstring before touching `available_resources`: the BPIC logs have no live capacity, so the evaluation pool *cycles* it through 0..3 while the full pool holds it at 3; the coherent BPIC policies are trained with `--random-resources` (initial free resources uniform in 0..3 per episode) so the pool's range is in distribution. SimBank's column is real (synthetic congestion from `build_resources.py`). SimBank is evaluated on every event (`rows="all"`); the `rows="decision"` variant is degenerate (proxy constant) and kept only as a diagnostic.
- `dual_level.py` holds the differentiable heads over the SB3 `ActorCriticPolicy` (`MarginHead`, `WaitMarginHead`, `CriticHead`, branch-wise logit heads), the Integrated Gradients implementation (128-step straight path, reference = pool mean), the Captum multi-method comparison and `deletion_test` (guided / random×20 / anti-guided masking to the reference, paired SE). `dual_level_study` is the full 2×2 study; `fidelity_test.py` runs only the wait-side part the paper reports.
- `xai_methods.py` / `xai_metrics.py` / `xai_plots.py` / `run_xai_suite.py` reproduce the PPM-explainability literature (SHAP, LIME + CSI/VSI, permutation, ALE; parsimony, functional complexity, monotonicity, LOD, ConsisXAI reducts/core/AIC/BIC, cross-method agreement) on the same heads and pools. Every attribution function returns `phi` with `states.shape`, so `deletion_test` accepts any of them. `xai_metrics.FAMILIES` maps the four state features onto the event/case/control-flow families the reference metrics need. Documented deviations from the reference code: LIME continuous surrogate by default, +0.5-adjusted weight of evidence, `k=2` for LOD.
- `risk_model.py` retrains the outcome predictor behind the state (Shoush & Dumas's CatBoost, ensemble size 1) from the prepared logs under `PeerJ2023/prepared_data/` (git-ignored; `TIMING_PREPARED_LOGS`), using their split/encoding semantics reimplemented incrementally in `encode_prefixes` (verified against their materialised pipeline in `test_risk_model.py`; `foreign/common_files/` is their code, one path patched). Label `deviant` = application not accepted (BPIC) / case cancelled (SimBank, our label). `run_risk_suite.py` explains `logit P(deviant)` with TreeSHAP on the pool's prefixes (matched by case id + prefix_nr; the RL CSV is exactly their test split), computes the Stevens & De Smedt metrics with real event/case/control-flow families, the deletion test, and two-level cards (risk + timing). Key data facts: `deviation = 1 - predicted` where class 1 is the *bad* outcome, so `deviation = 1` means "predicted to end well"; on BPIC2012 `reliability == deviation` exactly.
- `effect_model.py` retrains the third model behind the state: CausalLift's two-model estimator (per-arm `XGBClassifier(max_depth=3, n_estimators=100, lr=0.1)` with IPW weights from a `LogisticRegression` propensity), Y=1 deviant, T = the case's `treatment` flag, one-hot categoricals, `time_to_event_m` dropped. `run_effect_suite.py` explains logit p_T and logit p_U with TreeSHAP summed back to raw attributes, takes φ^CATE = φ^{p_U} − φ^{p_T} (toward a larger benefit), runs the deletion test on the effect log-odds ratio, and draws three-level cards. On SimBank the estimator is fit on the four events both arms share (every HQ contact in the log happens at event 5, every skip at event 9/10) and the untreated arm is a `ConstantArm` (skipping always cancels); `simbank_resources/add_effect_features.py` scores every event into `simbank_resources/data/simbank_time_contact_hq_with_effect.pkl` (`paths.SIMBANK_EFFECT_PKL`, columns `Proba_if_Treated/Untreated`, `y1/y0 = 1[p < 0.5]`, i.e. predicted *good* outcome, so the reward pays where the contact is expected to save the application).
- `compose.py` / `run_compose_suite.py` / `test_compose.py`: the composition operators. `rebuild_state` rebuilds the six-feature state from the retrained models (`risk_features_from_r` encodes the offline phase's rules: `deviation = 1 − 1[r > 0.5]`, `reliability = deviation` on BPIC2012 and `max(r, 1−r)` on BPIC2017); `propagate` splits each `φ^ΔQ_i` of a lower-level coordinate among the prefix attributes in proportion to `φ^{m_i}_j / Σ_k φ^{m_i}_k` (risk coordinates through `φ^r`, `p_T`/`p_U` through the per-arm TreeSHAP), keeping the channels (`risk`, `effect_T`, `effect_U`, `native`) apart and conserving completeness; a lower-level attribution whose sum is below `FALLBACK_RATIO` of its `|φ|` mass is split by `|φ|` and counted. `cancellation` gives the index c_j = 1 − |Σ channels| / Σ|channels| per attribute/state (risk-like attributes raise both effect arms and cancel; effect-like ones move one arm; this is the failure mode DeepLIFT's RevealCancel rule was built to catch in the plain Rescale rule `propagate` uses, Shrikumar et al. 2017), `well_defined` the non-degeneracy condition (share of states with |Σφ| ≥ ratio·Σ|φ| per coordinate), `baseline_alignment` the gap between an explainer's baseline and the pool mean logit, `sign_groups` the agree/oppose/independent split of `risk_effect_agreement`. The effect arms' TreeSHAP is interventional against `--n-background` pool prefixes by default (`--background pool`), which aligns their baseline with the timing level's pool reference; CatBoost only supports the path-dependent explainer, so the risk channel keeps it and the suite reports the gap. `anchor_to_direct` is the per-decision safeguard: the direct attribution of F as the input attribution, split among channels in proportion to the propagated channel masses (cards carry `anchored_flows`, `direct_top`, `direct_vs_propagated`; `figures/make_composition_flow.py --source anchored`). `EndToEndBox` is F(x, n) = ΔQ(s(x, n)) over the 76 prefix attributes + 2 natives (BPIC2017; 45 + 2 on BPIC2012), with `shapley_sampling` (permutation sampling, one shared permutation per draw; **against the pool background** by default, one background prefix drawn per state and permutation, so it sums to F's distance from its pool expectation -- with a single point reference the direct attribution explains the distance from a prefix the policy acts on and its per-state agreement with the propagated one drops from 0.77 to 0.61) and `deletion_test_e2e` (guided by any ranking vs. random ×20 vs. anti). `channel_test` validates the *paths* rather than the ranking: for each decision's top-5 composed attributes it sets the attribute to the pool reference in the input of one lower model only (risk, treated arm, untreated arm) and compares the margin change with the traced channel (sign, Spearman), and compares hiding it in all three models with the sum of the single-channel changes (measured cancellation, split by whether φ^{p_T} and φ^{p_U} share a sign). Effect channels and cancellation hold; the risk channel does not on BPIC2017 (sign ≈ 55–68%), because the policy reads r through `deviation`'s threshold and `reliability = max(r, 1−r)`. The suite runs every operator on two *readings* of the state, `shipped` (the CSV's numbers) and `rebuilt` (retrained models on the same prefix): on `cate_retrained` the two coincide (flip rate 0), on `cate` they do not. The paper's decision points are `pools.paper_card_indices` on the shipped margin, so Figs. 3/5/flow show the same cases.
- `risk_retrained` (`pools.VARIANTS`, `COHERENT_VARIANTS`; **stale**: its checkpoint and `*_risk_retrained.json` predate the reward-sign fix and `--random-resources`, and the paper no longer uses it): the cate recipe on the coherent CSV *without* the effect features (released four-feature state), the composition with a live risk channel; always-wait is optimal for it, so it only has a wait side; no SimBank checkpoint (compute_gain_table.py / fidelity_test.py skip logs without one). `compose.py` and the suite take the state's feature list from `pools.evaluation_pool`, so 4- and 6-feature states both work.
- Policy variants: `pools.VARIANTS` + `paths.variant_model()` → `models/variants/ppo_<log>_<variant>.zip`; `paths.bpic_csv(log, variant)` picks the CSV (`cate_retrained` → `paths.retrained_csv`, else the shipped one) and `pools.treatment_col` the historical-action column. `cate` = `--extra-features Proba_if_Treated Proba_if_Untreated --episode case --reward-scale 0.01 --ent-coef 0.3` (the only recipe that intervenes); `cate_retrained` is the same command with `--csv data/retrained_state_<log>.csv --out models/variants/ppo_<log>_cate_retrained`. Both BPIC checkpoints use **600k steps** (`--timesteps 600000`; the 300k ones are archived as `*_300k`; on BPIC2012 600k gives 42.3 vs 40.3 at 300k). On BPIC2017 at 300k it over-intervenes (33.6%, precision 0.38, gain 21.4 vs 24.8 always-wait; a second seed gives the same, `ppo_bpic2017_cate_retrained_seed7_manifest.json`; archived as `ppo_bpic2017_cate_retrained_300k.zip`), at 600k it intervenes on 15.9% with precision 0.73 and earns 39.9 (oracle 54.4). Lower entropy collapses to never-intervene on the coherent state too (ent_coef 0.02 / 0.05 / 0.1 at 300k: 0 interventions; 0.1 at 600k: 2.2%, gain 28.6) -- the sweep lives in `models/variants/sweep/` (git-ignored; `evaluate_checkpoints.py` scores checkpoints on the gain sample). Note SB3 drops the `.zip` suffix when the output stem contains a dot (`ent0.3`); rename before loading. SimBank's `cate` checkpoint is `models/variants/ppo_simbank_cate.zip`, trained by `simbank_resources/train_ppo_simbank.py --data <effect pkl> --extra-features Proba_if_Treated Proba_if_Untreated --reward-scale 0.01 --ent-coef 0.3`; `--variant released` on SimBank is the uncertainty-proxy checkpoint with the 4-feature state (`paths.simbank_pkl(variant)` picks the pkl). Negative results kept with manifests: `cate_stream` (released stream episodes: intervening forfeits the +50/+100 per-row rewards of unrelated cases), `cate_noent` and `cate_ent002` (per-case episodes but the actor collapses to never-intervene within ~5k steps; approx_kl and entropy reach 0 while the critic still learns V(ite>0) ≪ V(ite≤0)). A hand rule "intervene at the first positive-effect event" returns 859/case vs 594 always-wait on BPIC2012, so the target policy is learnable from the state. Always-wait is optimal under the released state (P(ite>0 | s) ≤ 0.27 everywhere vs. a ≈0.6 per-row break-even). Per-case oracle beats always-wait in 35% of BPIC2012 cases and 3.6% of BPIC2017 cases. `fidelity_test.py --variant <v>` also runs the intervene-side test when ≥30 intervene states exist.
- `foreign/train_ppo_fast_rl_prescriptive_monitoring.py` is the environment the BPIC checkpoints were trained in: Shoush & Dumas's *released* 4-feature state (relative_position, reliability, deviation, n_resources) and reward (cost 25 / gain 50 / gain_res 50), not the 11-feature state of their published paper. A resource is consumed only by the intervention, which ends the episode, so under the released reset the policy never sees `available_resources ≠ 3`; `--random-resources` (used for `cate_retrained`) draws the episode's initial resources uniformly from 0..`--resources` instead. Checkpoints trained without it (`released`, `cate`, `risk_retrained`, the `_300k` archives) only ever saw 3.
- `simbank_resources/` contains the SimBank pipeline: `build_resources.py` (Poisson arrivals + greedy server assignment; an extension of ours, not SimBank's design), `train_ppo_simbank.py` (`SimBankHQEnvFast`, whose `_df` is also what `pools.load_simbank` reads so features cannot drift), `tune_cost.py` (one-off diagnostic). `ite_proxy` there is a z-scored uncertainty proxy, not a causal effect estimate.
- `models/` and `simbank_resources/models/` hold the checkpoints with `_manifest.json` (seed, steps, provenance, and the history of failed SimBank runs), `_monitor.csv`, `_training_curve.csv`. The stray `_vecnormalize.pkl` is unused: the shipped checkpoint was trained without VecNormalize.

## Conventions

- **No leakage.** `risk_model.LEAK_NOTE` lists every input removed because it carries the future of a case (time_to_event_m; whole-case NumberOfOffers; BPIC2017 CreditScore, non-zero only on the offer that ends up accepted, with Accepted/Selected), and `risk_model.add_decision_points` restricts every model and state to *decision points*: prefixes before the first outcome-revealing activity (`outcome_activities`, incl. O_Accepted/O_ACCEPTED) and before the treatment (`treatment_activity` for the `treatment_nth` time: 2nd O_Created / O_SENT on BPIC, IV Antibiotics on Sepsis), which also defines the case-level treatment flag (replacing Shoush & Dumas's `treat` = at most one offer). Static attributes are the value known so far. The coherent RL CSVs have no `case_length`: `relative_position = prefix_nr / progress_horizon` (95th percentile of decision points per case in the training split). Run `leakage_audit.py` after touching any of this. Sepsis passes the audit but has almost no treatment overlap (propensity in [0.1, 0.9], the Crump et al. 2009 band, on ~8% of decision points): its effect level is not causally credible. `released`, `cate`, `risk_retrained` and SimBank artefacts predate these rules.
- **Reward sign.** `Proba_if_Treated`/`Proba_if_Untreated` are P(undesired | arm). The reward's `y1`/`y0` are the *desired* outcome, `compose.desired_outcome(p) = 1[p < 0.5]`, and the positive-effect rule is `compose.positive_effect_rule` (p_T < 0.5 ≤ p_U); φ^CATE = φ^{p_U} − φ^{p_T}. Shoush & Dumas's released `prepare_data_for_RL_V2.py` thresholds `p > 0.5` on the same P(deviant) columns, which pays for intervening where the treatment is predicted to cause the bad outcome; the shipped CSVs (and so `released`/`cate`/`*_cate.json`) keep that inverted reward. Everything built by `build_retrained_state.py` / `build_sepsis_state.py` uses the corrected rule. Pre-fix artefacts are snapshotted in `archive/pre_reward_fix/` (git-ignored). Never threshold these probabilities by hand: call the two helpers.

- Results are compared against the committed JSONs; `fidelity_results.json` reproduces bit-for-bit (checked under numpy 1.26 and 2.5). If a change alters numbers, say so explicitly and update the paper's tables (Sections 5.3, 6, 7) in the same change.
- Wait states are `margin <= 0` (equivalently `wait_margin >= 0`); intervene action index is 1.
- Scripts print a human-readable summary and write JSON; figures go to `figures/out/` (git-ignored) unless `TIMING_PAPER_FIGURES` / `TIMING_XAI_FIGURES` redirect them.
- Nothing has been committed in this working tree yet for the `paths.py`/`pools.py` refactor, `foreign/`, or the XAI suite; `run_dual_level_ppo.py` is staged for deletion. Check `git status` before assuming history.
